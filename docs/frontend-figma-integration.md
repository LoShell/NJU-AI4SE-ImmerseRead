# Figma 页面直接接入记录

日期：2026-10-27。范围：前端接入；后端接口、数据库和 Agent 未在本轮改造。

## 来源与边界

页面直接采用用户提供的 `沉浸式小说阅读器设计.zip` 导出源码。工作区根目录 `frontend/src/app/App.tsx` 是同一份页面参考，已核对 SHA-256；原参考目录与压缩包保持不变。业务仓库 `frontend/src/app/App.tsx` 使用其 JSX、Tailwind 类、内联配色、四主题、设置面板、两侧栏、选区工具栏和底部音乐栏。

新增的书库选择和音乐上传弹窗用于承接原型中尚未接线的按钮，沿用原型的卡片、颜色和圆角。手机宽度下增加侧栏覆盖规则，避免展开时将正文挤出屏幕。字体沿用原导出的 Google Fonts 声明，网络不可用时使用声明中的系统字体回退。

只安装页面实际需要的 `lucide-react`、`tailwindcss` 和 `@tailwindcss/vite`；没有导入原导出包的整套 MUI、Radix 或 shadcn 依赖。归属说明保存在 `frontend/FIGMA_ATTRIBUTIONS.md`。

## 数据接入

- `src/app/useReader.ts`：把现有领域模型与 Repository 转换为设计页面需要的数据和事件。显示用章节序号映射到原始 Segment ID，持久化继续使用原 ID。
- `src/storage/libraryRepository.ts`：新增书库列表读取，其余沿用已有 IndexedDB 数据源与 schema version 1。
- `src/reader/textFileReader.ts`、`txtParser.ts`：沿用既有解码、章节识别与兜底分块。
- 书库入口：左上“书架”或折叠侧栏的列表按钮；刷新按最近选书恢复。
- 原书籍、章节、批注、聊天和上传音频保留在原 IndexedDB；新增偏移/范围字段为可选字段，不进行清库或后端迁移。
- 设置、音量和最近选书标识保存在 localStorage；小说和音频仍保存在 IndexedDB。

## 用真实行为替换模拟

设计稿中的示例书籍、示例批注、模拟消息和固定曲目已移除。聊天使用 `/api/llm/chat`，氛围使用 `/api/llm/atmosphere`，状态使用 `/api/health`；保留开发服务器 `/api` 代理。

聊天与氛围支持 AbortSignal；切书、切章和聊天取消会丢弃迟到结果。HTTP 错误和网络错误显示为失败提示，不再冒充“未配置”的成功回复。默认不自动调用聊天或氛围模型。输入法组合输入时 Enter 不发送消息。

音乐栏操作同一常驻 audio 元素；切章、切面板和折叠音乐栏不会卸载播放器。已接入播放、暂停、前后曲、音量、列表/单曲循环、推荐切换确认、锁定、本地音频上传与删除。上传时可填写推荐使用的标签，旧曲目的既有标签继续保留。

批注使用实际 DOM Range 计算 UTF-16 偏移，避免重复句子的 `indexOf` 错位；正文以精确文本节点展示，换行和 emoji 的偏移与存储一致。选区工具栏支持保存批注、带片段提问与复制，批注可删除。

## 阅读位置与范围

切章不把整章标记为已读。前端观察正文视口中的字符区间，合并已见范围，保存滚动比例以恢复位置；不把跳过的章节自动补为已读。聊天、氛围及旧消息展示使用当前范围裁剪。进度写入采用防抖与顺序队列；切书前刷新队列。

旧进度恢复所选章节；没有滚动比例的旧记录从该章起点打开，不推定历史已读区间。新进度恢复章节和滚动比例。原有聊天范围无法证明可见时暂不显示，原始记录仍保留。已读百分比表示页面观察到的文本覆盖，不代表能验证用户确实阅读。

这仍是浏览器端范围控制。后端目前接收客户端上下文，不能独立核验正文/范围；服务端范围快照、检索、角色记忆和绝对防剧透均不属于本轮已完成能力。

## 验证

在 `frontend/` 执行：

```powershell
npm ci
npm run test
npm run build
npm run e2e
```

项目当前 Vite 要求 Node `^20.19.0 || >=22.12.0`。本机使用 Node 24.14.1；若使用 nvm，先切换满足版本要求的 Node。首次在新机器运行浏览器测试时，需用 `npx playwright install chromium` 安装测试浏览器。

Playwright 使用独立的 5190 端口与隔离浏览器数据，不操作用户 5173 页面中的书库。覆盖真实 IndexedDB 的书籍/位置恢复、重复文本批注、跳章范围过滤、迟到聊天取消、常驻音频、音量、手机宽度与主题恢复，以及上传音频的持久化和删除。聊天/健康接口在浏览器测试中用固定响应验证协议与状态，不能据此宣称真实模型已验证。

最终验证：13 个单元测试文件、58 项测试全部通过；7 项 Playwright 浏览器测试全部通过；`tsc -b` 与 Vite 生产构建通过，`git diff --check` 通过。浏览器测试截图与失败 trace 在被 Git 忽略的 `frontend/test-results/` 中。用户现有开发页已人工查看，确认显示导入后的 Figma 布局。

本轮没有调用真实 LLM，也没有变更后端。原型颜色、布局和样式作为视觉基准保留；深度可访问性审计、长书性能测量和后端首次迭代仍待后续完成。

## 前端收尾补充

用户已反馈完成真实模型配置并观察到聊天历史随阅读范围隐藏、返回后恢复。此为人工反馈，与自动化固定模型响应测试分开记录。

新增管理操作统一使用 `ReaderAction`、`ReaderHint` 与 `ReaderDialog`，删除按钮改为 Lucide 垃圾桶图标与悬停说明；批注/本地音频删除均先确认，失败时保留确认目标。音乐曲库、书库选择、通知、循环模式控件采用相同的主题参数与交互状态。新增 UI 的持续约定见 [视觉约定](../frontend/STYLE_GUIDE.md)。

上传入口与书库增加重复导入提示；聊天显示被当前范围隐藏的历史消息数量。AI 换曲锁定会隐藏已有建议、撤销待确认切换，并阻止迟到分析结果恢复换曲入口；解锁后可重新查看建议。手动切歌和列表播放继续可用，实际换曲后解除旧曲目的锁定。

新增浏览器验证覆盖历史隐藏提示与返回恢复、锁定前后的已有/迟到音乐建议，以及删除确认的取消与提交。数据库选型讨论不构成已迁移；当前数据仍保存在 IndexedDB。
