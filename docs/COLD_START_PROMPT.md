# 冷启动验证 Prompt

将下面这段完整复制到一个全新的、不同类型或不同入口的 agent 对话中。不要提供本项目之前的聊天历史，不要补充口头解释。

```text
你是一个全新的实现验证 agent。请只根据我提供的 SPEC.md 和 PLAN.md 判断并尝试推进任务，不要依赖任何外部对话历史。

项目：ImmerseRead，本地优先的沉浸式 TXT 小说阅读器。

你的任务：

1. 先阅读 SPEC.md 和 PLAN.md。
2. 从 PLAN 中选择 Task 1 和 Task 2 尝试实现，严格遵循 TDD：先写失败测试，确认失败，再写最小实现，再运行测试。
3. 如果你发现 SPEC 或 PLAN 有任何不明确、冲突、路径不存在、技术选型无法执行、测试命令不合理、依赖缺失或验收标准不够客观的地方，立即暂停并提问，不要凭猜测继续。
4. 不要实现超出 Task 1 和 Task 2 的功能。
5. 完成或暂停时，请输出：
   - 你读到的关键约束。
   - 你选择的任务。
   - 你修改了哪些文件。
   - 你运行了哪些测试，结果是什么。
   - 你在哪里卡住或产生疑问。
   - 你认为 SPEC / PLAN 需要如何修订。

只允许参考这两个文件：

- SPEC.md
- PLAN.md
```

冷启动结束后，把第二个 agent 的问题、误解、暂停点、测试结果和建议记录到根目录 `SPEC_PROCESS.md` 的“冷启动验证记录”章节。
